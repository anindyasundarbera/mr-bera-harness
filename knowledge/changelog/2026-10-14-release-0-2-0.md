Bumped to **0.2.0** by owner decision. `ADR-2026-022` recorded this as the owner's because
it is a release act; it is now performed.

## Why minor, not major — measured rather than assumed

| Check | Result |
|---|---|
| Entries by kind | **14 added, 3 changed, 7 fixed** |
| `removed` entries | **none** |
| `BREAKING CHANGE` footers (excluding merges) | **none** |
| `!` markers in commit subjects | **none** |

Nothing was removed and nothing declared a break, so a minor bump states the change
truthfully. No semver policy existed anywhere in the repository before this — which is why
the basis is recorded here rather than left as a number someone chose.

## What 0.2.0 actually contains

**All six build-order steps** of `HARNESS_ARCHITECTURE.md` §9: extraction and a derived index
that rebuilds identically; the query API; the prompt compiler and its content-bound
fingerprint; proposal schemas and effect gates that execute nothing; the session ledger in
`git notes`; and instruction→prompt, which resolves or asks. Plus four capabilities built
beyond the order: the **usage dashboard**, the **runtime dependency audit**, **code
provenance** (`harness provenance`, checked by anchor hash), and the **generated handoff
facts** (`tools/refresh_handoff.py`).

The README's status section was also corrected: it said *"Build-order steps 1–5"* and then
listed step 6 in the next sentence. It now says all six, which has been true since
`ADR-2026-018`.

## The single source, proven again

The bump was a **one-line edit** — `harness.__version__` in `src/harness/__init__.py` — and
the derived metadata followed automatically, exactly as `ADR-2026-022` specified:

```
wheel:  mr_bera_harness-0.2.0-py3-none-any.whl
        Name: mr-bera-harness
        Version: 0.2.0
--version:  harness 0.2.0
```

No other file needed editing. `ADR-2026-022`'s decision was that the *code* is the source
because a running harness must carry the value for `--version` and the dashboard provenance;
this release is the first time that decision paid off.

## What this makes possible, and what it does not

`mr_bera` pins the harness at `d029f3f`, which is now behind `main` (`f97625a`). With the
version changed, a moved pin is now **effective** for an existing environment — which it was
not while both revisions reported `0.1.0` (measured in `CHG-2026-024`: `pip install -e .` left
a 16-file installation untouched). **The `mr_bera` pin bump is a separate change, in that
repository, and is not performed here.**

**Not done, and recorded as the owner's:**

- **No git tag.** The repository still has **none**. A tag would let consumers pin by tag
  instead of by sha (`ADR-2026-022`'s open item, and `mr_bera` `ADR-2026-008`'s).
- **No semver policy.** This release records its basis; it does not establish a policy for
  the next one.
